# iOS App Proxy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add app-only manual and Shadowrocket subscription proxying, including the Linux guest, with explicit system-service boundaries.
**Architecture:** Extend the existing single Go runtime and local nethub; route native and WebKit clients through it and add transparent guest socket forwarding. Strict routing fails closed.
**Tech Stack:** Swift/SwiftUI, Objective-C/C, Go, sing-box, WebKit.
**Spec:** `docs/superpowers/specs/2026-11-08-ios-proxy-design.md` (approved 2026-11-08).

## Global Constraints

- Only affect OpenMinis; no global VPN or MDM.
- One Go runtime; no second c-archive runtime.
- Strict routing must not silently send TCP, UDP or DNS directly.
- iOS system services cannot be guaranteed proxied; disable controllable unsupported features in strict mode.
- Bind iSH changes to commit `0fd17a135e78b7a0cf08a4f5831217bbb76ed22f`.
- Linux execution cannot certify Xcode builds or iPhone runtime behavior.

## Review Focus

- Core/entry death and unknown route must fail closed (Task 2).
- Encoded subscription parameters and unsupported transports must not be silently altered (Task 3).
- Nonblocking sockets, UDP source addresses and DNS must preserve guest semantics (Task 1/5).
- WebKit popups, SDK sessions and non-HTTP backup traffic must not bypass routing (Task 4/6).
- Bootstrap, switching and background restoration must not create unannounced direct paths (Task 7).

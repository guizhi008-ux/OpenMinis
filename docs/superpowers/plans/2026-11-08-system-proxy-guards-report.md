# iOS system-service strict proxy boundary report

Date: 2026-11-08. Scope: controllable CloudKit, iCloud Drive, external File Provider access, and system-hosted OAuth launches. This report does **not** establish on-device network egress coverage.

## Implemented behavior

The synchronous, thread-safe `AppProxyNetwork.strictEnabled` snapshot is checked before starting system-managed connections. `Notification.Name.appProxyDidChange` is observed on the main queue; observer work hops to the main actor. No cloud enable preferences, category selections, mounted-folder bookmarks, write consent, or backup destination selections are reset.

- `CloudSyncEngine`: v1 startup, fetch/send, dirty preparation, force sync, discovery, and cloud deletion are gated. Startup rechecks after actor awaits. The delegate refuses to supply upload batches while strict. On activation the engine is detached, timers/scanner and pending sends stop, and `cancelOperations()` is requested. Disabling strict resumes only when the saved v1 preference is on and v2 does not supersede v1.
- `SyncCore`/`SyncV2Bootstrap`/`ICloudSharedZoneTransport`: startup, sends/fetches, direct session queries, recent polling, zone creation, and legacy deletion are gated. Direct CloudKit operations recheck at submission and pagination boundaries. Mode activation stops transports, cancels the recent-fetch timer, completes pending send/fetch waiters with an error, requests engine cancellation, and cancels the tracked legacy deletion operation. Upload delegate batches are withheld immediately. Turning strict off resumes the enabled v2 engine without changing consent.
- `MigrationEngine`: automatic migration/resume/count checks and cloud zone inventory/purge/delete helpers are gated. Paginated queries recheck before each submission. Existing migration progress is preserved.
- `DebugJSONRPC`: direct CloudKit query, zone enumeration, and zone statistics endpoints return a clear failure rather than bypass the sync engine gate; pagination rechecks the mode.
- `ICloudBackupManager`: ubiquity-container access, backup/restore/delete, and placeholder download are gated; backup upload rechecks after local staging. Listing yields no cloud results and supplies the pause explanation while strict.
- Provider OAuth managers for Claude, Codex, Gemini, Antigravity, OpenRouter and xAI reject login before starting a system browser and recheck immediately before presenting `SFSafariViewController`. MCP authorization similarly gates Safari and `ASWebAuthenticationSession`. Kimi and Copilot device-login sheets show a failure at start and before opening Safari. Token refresh remains managed by the shared app networking layer.
- `MountedFoldersManager`: strict mode suppresses bookmark resolution/activation, writability refresh, and provider materialization. On activation it cancels its activation pass, releases scopes, removes guest mount symlinks/snapshots and clears effective active URLs. Metadata/bookmarks remain. Delayed resolution results cannot reactivate a scope while strict; materialization and provider-domain signaling recheck the snapshot.
- `MountedFolderCoordinator` and iOS `FileToolIO`: external coordinated file operations and new ubiquitous downloads are blocked. App-container files remain available. FileToolIO's Foundation-only standalone build retains no dependency on app proxy types when UIKit is unavailable.
- `BackupDelivery.copyToMountedFolder` blocks unattended copies to all external destinations because local-only File Provider behavior cannot reliably be established. Selected destinations remain saved; delivery errors use the existing per-destination failure result. Backup Share/Save to Files sheets present the pause explanation rather than constructing a system export controller while strict. `BackupOpenRouter` and `ExternalFileImporter` reject external provider reads before acquiring scopes.
- Native player offload, fullscreen/thumbnail video, audio artwork and `GlobalAudioPlayer` now require file URLs before AVFoundation input; external local provider paths also pass the strict file-access gate. The Share Extension rejects non-file URLs in image/file materialization rather than allowing `Data(contentsOf:)` to download independently of the proxy. It does not link the app proxy core.
- v1/v2 cloud settings, debug iCloud backup settings, and mounted-folder settings show the strict-mode pause explanation and update it when the proxy mode changes.

`SystemProxyBoundary` is declared in the already-compiled `Shared/EnvVarStore.swift`; it is unrelated to env-var persistence and was placed there to avoid concurrent project-file changes. Its file-access check is lexical to avoid triggering provider XPC during symlink resolution: app home, app temporary storage and MinisFileProvider app-group data are allowed; known guest mount paths and external roots are rejected. Explicit mounts are also deactivated at the manager boundary. This is not a general sandbox or a proof against arbitrary app-local symlinks/previously acquired handles.

## Unsupported / OS-owned paths and remaining limitations

These limitations must remain visible in product claims and device acceptance criteria:

1. **Already delegated operations:** `CKSyncEngine.cancelOperations()`, operation cancellation, task cancellation, scope release and removed symlinks are best effort. They cannot recall every request, open file descriptor, system browser page, file-provider task, or upload that iOS accepted before the transition. Direct async CloudKit queries already submitted to the daemon may complete. No claim is made that toggling strict retracts existing OS work. An already presented OAuth browser is not forcibly dismissed by these new guards; new launches are blocked.
2. **iCloud Keychain:** `ProviderKeychainHelper` in `Providers/ProviderConfigStore.swift` saves synchronizable API keys, OAuth tokens and related provider credentials. `EnvVarStore.saveValue` in `Shared/EnvVarStore.swift` updates/adds synchronizable env-var values. These paths remain OS-managed, including new writes while strict. Existing readers prefer synchronizable records, and the save paths delete/update or migrate existing items; changing only a sync flag would risk stale reads or losing credentials. No destructive migration or silent failed-save behavior was introduced. Existing iCloud Keychain replication cannot be retracted; strict proxy is therefore **not** a guarantee that these OS services stop networking. New proxy credentials are handled separately by the proxy implementation as local-only Keychain items.
3. **APNs:** the OS's shared push connection is outside application-controlled routing. No attempt is made to proxy or disconnect it. Notification registration/previous subscriptions may cause OS network activity.
4. **Other apps and Files:** a File Provider or another app can continue its own sync independently after scope release. A picker opened before activation may have already delegated work. The app's own `FileProvider` extension serves app-group local files; its enumerator signals are local OS coordination, not an implementation of a proxy for third-party providers. General user-invoked share sheets and `UIApplication.open` links elsewhere in the app can hand data/URLs to another app. Backup-specific exports are gated here; generic skill/chat/diagnostic export and other external-app launch UX require their own boundary policy. They are outside the controlled networking guarantee once the user delegates to another app.
5. **Incoming system shares:** `ShareExtension` receives data already materialized by iOS. App import guards cannot prevent OS download performed before the extension/app receives an attachment. Other specialized document-picker imports should be audited independently of the central external-file/backup paths.
6. **System device integrations:** speech recognition, device services, Bluetooth/HomeKit and other Apple SDK traffic are not made proxyable by these changes. They require explicit capability audit before any broader claim.
